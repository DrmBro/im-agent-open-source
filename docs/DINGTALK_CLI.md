# 钉钉与独立 Codex CLI

日期：2026-11-17。

状态：源码接入，尚未编译、安装或进行真实收发验证。现有安装不会自动获得此能力。

## 执行路径

飞书继续使用当前配置中的桌面提交方式。钉钉使用独立 `codex app-server --stdio` 进程，通过 JSON-RPC 创建和恢复会话，不依赖 Codex 桌面 CDP。

两个客户端复用同一套 CLI 发现、模型认证和配置目录，但进程、轮次订阅及执行请求分开。会话绑定的渠道决定执行路径，重启时从数据库恢复路由；不能将同一 thread 同时作为两种路径的执行目标。

收件箱去重、持久队列、发送者权限、日志观察、最终回复账本与恢复继续使用现有实现，不另建钉钉任务系统。钉钉会话加入同步扫描，但不标记为客户端自建群，归档不会解散用户已有群。

## 能力与配置

桌面客户端的 IM 连接清单增加“钉钉”。凭据沿用本地加密配置与钥匙串主密钥。

| 字段 | 用途 |
| --- | --- |
| Client ID / AppKey | 企业内部应用标识 |
| Client Secret / AppSecret | 应用凭据 |
| Robot Code | 应用机器人的发送身份 |
| Corp ID | 校验机器人及发送者企业身份 |
| 用户白名单 | 回调中的 senderStaffId，不使用昵称或 unionId |
| 管理员 | 必须属于白名单 |

需要应用机器人的 Stream 消息订阅及单聊、群主动发送能力。仅保存凭据不等于已经获得平台权限。

支持机器人私聊、已有群中的文本消息；群内需 @机器人。每个私聊或群入口绑定一个 thread。首次文本自动创建；绑定后的文本继续同一会话。同一会话仍使用现有队列，不在本次新增活动轮次追加输入。

支持 `/new`（未绑定入口创建）、`/status`、`/stop`、`/respond 请求ID 选项值`、`/archive`。审批和明确选项问题转换为文字指令，仍由原审批记录校验请求人、地址、状态和选项，不因文字输入绕过审批校验。

限制：不自动建群，不支持话题、创建表单、图片和附件，不提供可原地更新的互动卡片；不支持在已绑定入口通过 `/new` 替换 thread。独立会话使用另一钉钉群。归档后的旧入口保留记录，不自动复活。

由 IM 创建的新会话沿用现有 Full Access 规则，界面明确提示。钉钉不能作为公开机器人使用，白名单仅授予可信员工。

## 传输与故障语义

- Stream 使用官方 SDK v0.9.1 的协议模型与项目已有 WebSocket 库。该 SDK 版本的自动重连基于 Background；为使停止桥接能关闭连接，本项目管理有界并发、心跳和可取消重连，不采用其自动重连循环。
- 主动消息通过机器人 API 发送，不持久化临时 sessionWebhook，因此长任务和重启后的结果发送不依赖回调 Webhook 的有效期。
- processQueryKey 表示平台已接收请求，不是员工已读证明。平台未确认、超时、响应不完整等保留为不确定投递，不自动换接口重发。
- 请求错误不输出原始响应、令牌、消息正文或带 ticket 的 URL。
- 钉钉凭据不注入 Codex 子进程；清理遗留 DINGTALK 环境变量。
