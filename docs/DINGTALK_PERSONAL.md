# 钉钉个人账号（DWS）

日期：2026-11-17。

## 用途

在用户本人授权后，接收白名单联系人的单聊文字正文，由独立 Codex CLI 会话判断是否可以处理并生成待审草稿，默认经本人确认后再以本人身份发送，并保留钉钉的 AI 标记。飞书桌面通道和钉钉应用机器人仍使用原有独立连接。

## 接入结构

渠道类型为 `dingtalk_personal`。DWS 负责 OAuth、本地凭据保护、个人事件订阅和消息发送；IM Agent 不复制 OAuth Token。复用已有适配器注册、持久收件箱、队列、会话映射、最终回复账本和恢复观察。

已核对的 DWS 版本为 v1.0.68。默认程序位于 `~/.local/bin/dws`，也可以在连接配置中指定绝对路径。

配置使用精确的 `corpId:userId` profile，拒绝组织名称别名与多账号选择器。所有 DWS 调用均固定 profile，并移除继承环境中的 DWS 凭据、默认账号和端点覆盖。已有会话地址包含账号和联系人身份，换账号后不会向新账号重放旧会话回复。

## 白名单与启动

本人可显式开启 `personal_all_direct`（全部个人单聊）和 `personal_mentions`（群内 @本人）。分别使用 DWS 的 `user_im_message_receive_o2o_all` 与 `user_im_message_receive_at`，不读取群内全部消息。群消息独立绑定到原会话，审核面板显示回复目标；群回复不套用私聊自动回复规则。

- `profile`：DWS 已登录账号的精确标识。
- `self_open_id`：该账号本人的 openDingtalkId。
- `dws_binary`：可选的 DWS 程序绝对路径。
- 用户白名单：本人和允许接收、分析消息的联系人 openDingtalkId，最多 20 位联系人。
- 管理员：只允许填写本人 openDingtalkId。

个人渠道中的 openDingtalkId 与应用机器人回调中的员工 UserID 不同，不能混填。

没有登录时显示等待授权；未选择监听范围且没有联系人时显示等待配置。指定联系人模式订阅 `user_im_message_receive_o2o`，全部单聊与群@模式由本人显式开启。过滤本人发出的消息，避免自发自回。

用户授权和监听范围必须由本人确定；当前实现不会自动把已配置机器人的员工白名单转换为个人代回复联系人。

## 桌面审核与自动回复规则

默认模式为人工审核。模型输出 assessment、reason、reply，分别表示能否处理、理由和拟回复正文。无法解析、不确定、需要补充信息和需要本人处理的情况均不会自动回复。

“消息助理”页顶部的“会话产出的回复待你确认”展示原消息和可编辑草稿，支持保存、确认并发送、复制后自行回复、标记已自行回复和忽略。复制不会标记已发送；标记自行回复只记录本人声明，不伪造平台回执。分析失败时通知本人并保留待人工处理记录。

审核操作通过本机控制接口，绑定 event_id 和版本号。批准后才创建独立的实际投递片段，原始模型输出保留为分析证据；旧版本、已处理记录、已发送或不确定回执不能重新批准。收到更新消息时拒绝批准较旧的草稿，避免过时回复。

桌面通知不含联系人及聊天正文，只提示打开 IM Agent。通知投递依赖系统通知权限，消息助理页是可靠记录；通知尝试失败不触发对外发送。

连接配置中的 `personal_auto_reply_users` 默认空。本人显式选定的联系人，仅在规则生效后新收到的消息被判断为 ready 时自动批准；旧待审草稿、needs_info、manual 和解析失败均不追溯自动发送。关闭规则并重启后，尚未发送的自动批准片段继续受到规则检查。多人自动化之间是否会互相回复仍取决于双方规则，应从明确联系人开始设置。

飞书审核入口尚未实现。审核存储和操作服务与 UI 分离，后续可在完成操作者身份验证后复用。

## 会话与权限

### 群内补充

已移除群任务跟进面板、自动群订阅与候选相关性分析，不再收集未 @的普通群消息。群 @沿用原群绑定会话；平台推送的消息若包含引用信息，继续保留引用消息标识。仅引用但未 @不保证由 @事件推送，需要本人手动补充，或同时 @。

历史群跟进表保留用于兼容与审计，不再调度。忽略和标记自行回复属于本地收尾操作，原会话归档后仍可执行；实际发送仍要求有效的活跃会话和连接。

每个账号与私聊联系人组合或原群会话绑定一个 Codex thread。新会话复用配置的业务工作目录；没有配置时自动分配目录，已有会话保留自身目录。收到的斜杠文本作为普通聊天内容，不执行 `/archive`、`/respond` 等管理命令。

根据本人授权，新建及恢复的个人消息业务会话复用普通 IM 会话的 Full Access 权限并校验回执，不再额外禁用 Skills、MCP、Shell、插件或搜索，具体工具以本机 Codex 配置为准。模型主动查询和分析，确实缺少关键条件时才追问。历史会话中曾经声明无法查询的内容不代表当前工具权限。

最终仍输出审核结构，实际对外回复沿用本人审核与已有显式自动回复规则。执行工具的权限和回复发送审核是两个阶段：审核最终回复不等于工具执行前审批。模型提示词要求不通过工具自行发送联系人消息，联系人不能批准本机交互请求。



## 收件与发送语义

消费 DWS `--flatten --format ndjson` 的结构化事件，按账号、连接、会话和 message_id 去重。DWS 的事件源确认由 DWS 管理；桥接只能保证已成功持久化的收件，不承诺进程退出期间平台消息一定补投。

收件后复用原队列。联系人仅收到已入账的最终回复，不发送会话创建提示、执行进度、审批卡或内部错误。也不把本机手工修改的历史消息直接镜像给联系人。

发送使用个人身份、明确 openDingtalkId、标准输入正文、固定幂等键、AI 标记和投递回执查询。正文不放在进程命令行，避免参数列表泄露。既支持 DWS 原始回执，也核对统一 outcome/data 信封；只有确认消息 ID、幂等键及投递状态才记为成功。超时或不确定响应按既有账本隔离，不自动重发。

停止时向 DWS 发送 SIGTERM，让它清理本次订阅；超时后由子进程管理回收。DWS 自己管理共享事件总线，本项目不终止其他消费者的总线进程。

## 当前交付边界

已安装并校验 DWS，本机已完成本人登录与身份核对。本人已要求开启全部个人单聊和群@，默认均须审核。订阅就绪、真实收件、模型分析和审核发送分别核对，不把连接成功等同于完整链路验证。不下载附件，不读取未@本人的全部群消息，不主动发送测试消息。

平台或企业可能要求管理员批准 DWS 访问。登录失败不代表 IM Agent 构建失败；需要根据 DWS 授权页面处理。

## 协议依据

使用钉钉官方 DingTalk-Real-AI/dingtalk-workspace-cli v1.0.68 的本机命令帮助、事件 Schema，以及对应的 personal/output、helpers/chat_delivery、helpers/employee_chat_context、output/envelope 等源码核对协议。Codex thread 配置参考官方 temporary_structured_request 与 app-server-protocol 的配置覆盖实现。

仅调用 DWS 已发布程序，不复制其 SDK 或认证实现；没有向第三方发送任何测试消息。

## 手动投递 Codex 消息

“消息助理”页底部提供“投递 Codex 消息到钉钉群”。来源是本机 Codex 会话（含归档），每页最多30条公开消息，支持向前翻页；工具输出与内部推理不展示。超过24000字节的消息预览明确提示截取，发送正文可由本人编辑。

目标为已接入的钉钉群，也可显式填写其他群 conversationId；通过已配置的钉钉个人账号发送，保留 AI 标记。发送前预览账号、群 ID、来源消息与最终正文；不改变原会话绑定、单聊接入或同步规则。本地图片和附件链接不会自动上传。

来源消息、目标群、最终正文共同构成幂等身份，重复点击不重复投递。各分片独立记录平台回执；超时、取消或重启后不自动重发，界面显示已确认片段数和未确认状态。最近50条投递记录保留在入口中。后台重启会把未完成投递标记为待核对。

## 飞书状态卡投递

飞书会话状态卡增加“投递最新回复到钉钉群”。点击后固定当前最新已完成的助手回复，展示完整正文预览及目标群选择（可选填写1000字内的替换正文）；可选择已接入群或指定钉钉账号后填写其他群 ID。仅原会话创建者或飞书连接管理员可操作。确认使用既有消息投递账本，不改变源会话绑定。重复提交、超时和后台重启不自动重复发送。

钉钉指定消息投递使用 Markdown 消息类型；同条 Markdown 不按字符切开，避免破坏表格和列表。图片与本机附件链接显示未上传提示，不由发送命令隐式读取本机文件。

## 按钉钉会话分组选择群

桌面投递入口按当前钉钉账号的自定义会话分组显示树形目录，展开分组后加载群聊。保持接口返回顺序，过滤单聊；同一群属于多个分组时可分别展示，但最终使用同一稳定群 ID 投递。搜索按群名称或 ID 筛选全部群；“全部群（含未分组）”提供没有放入自定义分组的群入口。

飞书卡片采用分组→群聊两级选择：先选分组和可选关键词，再选择群并确认发送。每页最多50个群，可翻页或返回分组。导航不会发送消息，不需要填写群 ID。分组内容缓存1分钟；读取失败明确报错，不把不完整列表当空列表。

## 置顶群与最近消息排序

投递目录最上方增加“置顶群”，通过本人账号的置顶会话接口读取并过滤单聊，不把置顶当作普通自定义分组。

各分组和全部群按可读取的最近消息时间倒序显示。优先使用会话元数据，缺失时在后台最多4个并发任务中补查群内最后一条消息，仅保留时间，不保留正文。目录缓存1分钟，补查时间缓存15分钟，近期会话元数据每分钟刷新。读取中明确提示，桌面自动更新排序；飞书卡片可点击“刷新排序”。没有可读取时间的群显示原因并放在末尾，不伪造时间。

## 图片投递

指定 Codex 消息投递当前只发送文本/Markdown；图片和普通文件均不上传，图片位置会显示“图片未上传”。

支持 PNG、JPEG、GIF、WebP，每张最多20MiB，一条消息最多10个图片引用，总大小不超过40MiB。网络图片保留原 HTTP(S) 引用。本地图片使用 `![说明](图片路径)` 内联形式；引用式图片暂不支持。普通文件不上传，本地文件链接显示文件名称及未上传提示。

图片内容摘要纳入投递去重身份；完成后清理本次临时副本。发送超时或结果不明时保留账本，不自动换格式或重复发送。

## 消息助理（父 agent 分流）

原“任务看板”和“个人消息”页已合并为“消息助理”。它定时**主动拉取**今天（上海时间零点起）关注对象的消息，而不只依赖实时事件：

- 关注范围：设置中指定的人和群。搜人先匹配本机已拉取消息里出现过的发送人，再查通讯录（同一关键词缓存 30 分钟）；搜群在后台每 5 分钟刷新的全部群目录缓存中本地过滤，今天活跃的排前面，不输入关键词时只列今天活跃的群（活跃列表缓存 1 分钟）。可选包含今天 @我 的群；默认跳过机器人消息。
- 分析模型：直接调用 `~/.codex/config.toml` 当前供应商（CC Switch 写入），模型从 CC Switch 的模型目录中选择，例如 `deepseek-v4-flash`。供应商没有可用 API Key（如 ChatGPT 登录）时回退到临时 Codex 线程。
- 拆分事项：同一会话的新消息按批交给模型，拆成一个或多个“事项”。群里多人同时提的问题分开；对已有事项的追问归入原事项；一条消息可属于多个事项；闲聊不建事项。
- 三类判断：**需要我处理**、**可自动回复**（附可编辑的回复草稿）、**无需回复**。可在页面上纠正分类，最近的纠正会作为示例帮助后续判断；也可用自然语言补充三类规则和个人背景。
- 子 agent：需要我处理且需要多步工作的事项，自动派发为独立 Codex 会话（复用原收件会话链路，归入侧边栏“IM Agent”分组）。会话产出的回复仍进入待审。
- 新消息队列：已派发会话的事项再收到新消息时，**不直接插入会话**，而是写入持久队列。会话首条任务说明了队列的读取方式：`python3 ~/.codex/skills/dingtalk-message-context/scripts/pending_messages.py --thread <会话ID> [--consume]`。可选开启“会话空闲时提醒”，在会话没有排队或执行中的请求时追加一条提醒。
- 等待对方回复：你在关注的会话里向别人提问、索要东西或催办后，事项标记为“等待对方回复”（显示等谁、已等多久）。对方答复后自动清除；超过设置的小时数（默认 4）仍未答复时标红并发一次本机通知。可在事项上直接“发送催办”（发出后重新计时），也可手动标记或取消等待。等待中的会话跨天继续拉取，最多 7 天。
- 发送：可自动回复的事项默认只拟稿，由你点击“确认发送”；开启“直接发送”后不经确认发送。每次发送使用版本化幂等键，送达不确定时不自动重发。

设置保存在业务数据库 `assistant_settings`，保存后立即生效，不需要重启桥接。
