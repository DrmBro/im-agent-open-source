# 让 AI 逐步指导首次配置

将下面内容复制给能读取本仓库的 AI。此流程用于指导用户操作，不授予 AI 自动发布应用、修改凭证、重启 Codex 或发送业务消息的权限。

```text
请指导我从零配置 IM Agent，直到单次测试问题在 Codex 执行并回复到正确的飞书群。

先读取 README.md、docs/GETTING_STARTED.md、docs/CONFIGURATION.md、docs/DEPLOYMENT.md，核对当前代码/发行版本，不依赖旧聊天里的安装路径或账号。

开始先询问我的系统/芯片、源码还是安装包、Codex 是否已安装可用、是否已创建飞书自建应用。一次只指导当前一个动作，解释成功标志，等我反馈后继续。不要把一系列需要我操作的步骤扔进新文档让我自行执行。

按以下关口推进：环境与安装 → 实际 Codex CLI/协议兼容 → 桌面入口 → 飞书应用能力、权限、事件与发布 → 当前应用 Open ID → 本机凭证与钥匙串 → 网络及后台状态 → 首条任务。

不要向我要 App Secret、token、钥匙串密码、auth.json、数据库或完整配置文件。让我自己在本机界面填写。只接收脱敏的状态、版本和错误码，不用上传凭证换取诊断。

先做只读检查；安装/界面操作按我授权范围执行。使用 computer use 前先征得我同意。遇到 Codex 已运行但无入口，先让我保存工作并等任务结束，不自动杀进程或重启。不要自动启用登录自启、历史导入或实验性草稿恢复。

核对项目实际选中的 CLI，不能只检查 PATH 中的 codex。当前项目依赖 app-server --stdio 和部分项目/模型/历史接口；无法证明兼容时明确停止并报告，不猜测最低版本，不以最新版保证兼容。需要查外部资料时使用官方来源，飞书权限按当前应用后台与对应 API 核对，不虚构权限标识。

明确区分：本机配置已发现、后台运行、飞书已连接、桌面入口可用、模型完成、回复已送达。一个状态不证明下一个成功。

首次用自己的账号同时加入白名单和管理员，使用独立群，自动发现及历史导入关闭。通过私聊 /new 打开表单，把无敏感内容的测试问题填入首问，点击一次创建并开始。表单已提交首问，进入新群后不要再发一次。关闭自动切换时指导我手动打开准确目标会话。

遇到已提交但未确认、等待回复或未知送达，只核对原请求，不自动重发、不删除防重记录、不改权限绕过保护。需要审批时由我在对应界面处理，不自动批准。

验收记录：系统/芯片、IM Agent 提交号或版本、Codex 桌面版本/build、实际 CLI 版本，各关口的通过/失败/未验证，以及单次问题是否到达正确群。未测试附件、共享话题、归档就标未验证；不得宣称全部功能正常。
```

使用指南的错误分流表定位当前失败层。外部账号、管理员审批、签名/公证和不兼容的 Codex 版本可能阻止配置完成；AI 应解释具体阻碍及下一项可验证操作，不能用“应该可以”代替验收结果。
