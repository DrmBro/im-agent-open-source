# 从零配置到第一条回复

本指南用于个人 Mac 上首次部署。面向公开源码，不需要维护者的数据库、飞书账号、模型凭证或内部工具。需要 AI 指导时使用 [引导词](AI_SETUP.md)，由 AI 一次给出一个动作，确认结果后再继续。

## 先明确支持范围和验收边界

- 主要目标为 macOS Apple Silicon；现有打包脚本仅接受 arm64。Info.plist 中的最低系统版本字段不是实际兼容验收结论。
- 源码依赖 Go 1.24.0、Wails v2.12.0。前端没有 npm 构建脚本，但不应据此认定所有 Wails 工具链都无需 Node/npm；以 `wails doctor` 对所用版本的检查结果为准。
- 没有已验证的 Codex 最低/最高版本区间；不承诺安装最新版后即可兼容。发布记录应记录桌面版本、桌面 build、实际 CLI 版本与本次首次收发结果。
- 此文依据仓库实现整理，尚未在全新用户环境完成端到端验收。不把维护者已有环境可运行当作新环境成功证明。
- 首次使用保持会话发现、历史导入、纯文本草稿保留和自动恢复关闭。桌面自动切换可先关闭并手动打开目标会话。

## 第一步：准备并安装

安装自己的 Codex 桌面应用，完成自己的登录或服务配置，先在 Codex 中确认一个无敏感内容的问题能够得到回复。CC Switch 是可选配置工具，不是必须安装的软件；使用它配置的本地代理时，代理必须保持运行。

源码安装参见 [部署文档](DEPLOYMENT.md)。克隆后目录是 `im-agent-open-source`：

```bash
git clone https://github.com/DrmBro/im-agent-open-source.git
cd im-agent-open-source
go version
xcode-select -p
go install github.com/wailsapp/wails/v2/cmd/wails@v2.12.0
export PATH="$(go env GOPATH)/bin:$PATH"
wails doctor
go mod download
GOFLAGS=-trimpath wails build -clean
bash scripts/install-macos.sh build/bin/im-agent.app /Applications
```

Go、Command Line Tools 或 doctor 必需依赖缺失时，先按工具的官方安装说明解决，不继续尝试运行未生成的 App。`wails: command not found` 时检查 Go 安装目录和上面的 PATH；不需要以 root 运行桥接。

安装包用户需要与芯片匹配、来源可信的包。当前打包脚本生成未公证的 ad-hoc 包；被系统阻止时不能视作安装通过，也不要关闭 Gatekeeper。可选择自行从审阅过的源码构建，或等待正式签名、公证的发行包。

**通过条件：** `/Applications/IM Agent.app` 可以打开，能看到配置页面。本体无需用户在运行时安装 Go；源码构建需要开发工具链。

## 第二步：核对 Codex 版本及本机配置

在 IM Agent 的“Codex 配置”点击“重新检测本机配置”，记录它实际选择的 CLI，不要只看终端 `codex --version`，两者可能不同。在自己的终端对该文件执行只读检查：

```bash
"<客户端显示的 CLI 绝对路径>" --version
"<客户端显示的 CLI 绝对路径>" app-server --help
```

尖括号是需要替换的占位符，不是可直接执行的命令。不要向 AI 粘贴完整认证文件或配置文件。

| 检查项 | 当前实现的要求 | 失败处理 |
| --- | --- | --- |
| 配置来源 | `follow_local` 固定使用当前用户 `~/.codex`，不继承其它客户端的 `CODEX_HOME` | 特殊目录才改 `custom`，并选择真实配置目录 |
| 用户配置 | 能读取并解析 `config.toml` | 若官方安装未生成文件，按所用 Codex 版本创建合法配置；不要复制维护者的文件 |
| CLI 启动参数 | 当前源码执行 `codex app-server --stdio` 并传入配置参数 | 如果该版本帮助或启动报错不支持 `--stdio`，属于兼容阻碍。停止排查权限，向维护者报告版本；不要假定单独 `codex app-server` 能运行就兼容此项目 |
| 协议能力 | 新建表单用到 `project/list`、`model/list`，历史功能还依赖线程及分页接口 | 返回 method not found 或模型/项目列表无效时，记录具体阶段与 CLI 版本，不编造模型选项 |
| 模型可用性 | Codex 本身能实际完成请求 | 认证、额度、模型和代理问题先在 Codex 中解决 |
| 审批策略 | 保存支持 `untrusted` / `on-request` | CLI 帮助不再包含 `untrusted` 时，项目运行时改为只读沙箱 + 按需审批；界面有提示。不是保存失败，也不是自动授予写权限 |

若用户需要写文件，可在理解风险后显式选 `workspace-write` + `on-request`；不能为了“跑通”改成自动批准或无沙箱。桌面提交是在已有桌面会话中执行，仍须检查该会话实际权限，不能把辅助 App Server 的参数当作桌面会话权限保证。

**通过条件：** 本机配置可读、实际选中的 CLI 与当前项目启动方式兼容、Codex 自身能回复。CLI 被发现只是其中一项。

## 第三步：确认桌面提交入口

推荐的 `native_queue` 模式需要桌面连接，不能只启动 CLI。

在“Codex 配置 → 桌面启动与连接”点击“检测桌面与连接入口”。多个安装副本时，选择实际使用的应用，再检测。项目核对应用标识和签名，改名不等于身份匹配；签名不匹配的修改版不能当作官方兼容安装。

| 状态 | 下一步 |
| --- | --- |
| 入口可用 | 继续配置；这尚未验证模型执行与目标会话提交 |
| 桌面未运行 | 点击“启动桌面并检查本机连接”，阅读确认提示后启动 |
| 桌面运行中，入口不可用 | 保存工作、等待任务结束，由用户自行正常退出 Codex 后重新检测与启动；AI 不杀进程或强制重启 |
| 未找到应用 / 身份校验未通过 | 核对安装位置和官方应用身份，不修改签名检查绕过 |
| 连接地址不安全 / 桌面进程不唯一 | 排查非回环监听或重复实例，状态明确后才继续 |
| 启动结果待确认 | 只读复查，不反复启动、不提交任务探路 |

自动启动入口扫描标准 Applications 目录；不依赖 Codex++。推荐端口及默认候选端口必须由该桌面进程持有且仅监听回环地址。自动探测默认范围为 9222–9235；不要公网映射、局域网开放或使用 `0.0.0.0`。

**通过条件：** 页面显示“入口可用”，应用身份、进程和回环入口核对通过。`direct` 是另一条提交路径，不能当作桌面故障的无条件替代，它不保证相同会话交互行为。

## 第四步：建立飞书自建应用

在飞书开放平台创建企业自建应用并启用机器人能力。当前适配器使用 `open.feishu.cn`；不能默认把国际版 Lark 的凭证视为兼容。

### 权限与事件

下面权限标识供后台搜索与逐项核对，按实际 API 页面列出的可选授权授予必要项，不是要求把所有管理权限一次性全开。飞书可能调整权限拆分、名称和租户审批；以该应用后台及 API 文档为准。当前文档抓取只能取得部分官方页面壳，以下是按仓库调用整理的核对清单，未在新租户逐项验证。

| 能力 | 后台权限核对项 | 对应使用点 |
| --- | --- | --- |
| 私聊收消息 | `im:message.p2p_msg:readonly` | 私聊 `/new` 等消息 |
| 群内普通文字 | `im:message.group_msg` | 用户无需每条都 @ 机器人；仅 `im:message.group_at_msg:readonly` 不能覆盖普通群消息场景 |
| 以机器人发消息 | `im:message:send_as_bot` | 文本、回复、表单和状态卡 |
| 读取消息历史 | `im:message:readonly` 或接口要求的消息读取权限 | 收件对账使用消息列表接口；有实时事件不代表历史读取成功 |
| 创建、查询、更新群 | 在群接口中核对 `im:chat:create`、`im:chat:read`、`im:chat:update`，或后台提供的相应 `im:chat` 权限 | 新建会话群、读取群属性、更新群名 |
| 以群主管理群 | `im:chat:operate_as_owner` | 代码建群时设置机器人管理能力，后续自动解散依赖此权限与实际群权限；仅勾选权限不能让机器人获得任意群控制权 |
| 上传图片和文件 | `im:resource` | 图片与文件上传 |
| 下载消息附件 | 消息资源下载 API 要求的读取权限及资源访问条件 | 下载用户发送的附件；上传权限不等于能读取任意文件 |
| 更新卡片 | 消息卡片更新 API 要求的权限（核对 `im:message:update` 或相应消息权限） | 状态卡更新；消息由本机器人发送且在可访问范围内 |

使用长连接接收事件。配置以下订阅，并确认卡片回调也选择支持的长连接方式：

| 事件标识 | 用途 | 首次验证 |
| --- | --- | --- |
| `im.message.receive_v1` | 接收消息 | 私聊 `/new` 后出现表单 |
| `card.action.trigger` | 表单提交、交互卡片按钮 | 点击“创建并开始”后表单进入处理状态 |
| `im.chat.disbanded_v1` | 群解散同步 | 首次收发不主动解散群；需要双向归档时另行验证 |

只有订阅消息事件，没有卡片回调，会出现“表单能收到，但提交没有效果”。长连接不需要部署公网回调服务器，不要为此开放本机控制接口。

按开发者后台要求创建并发布应用版本，完成租户管理员的权限审批和安装/可用范围配置。首次使用者必须在应用可用范围内，且能找到机器人并发起私聊。新增权限或事件后检查是否需要重新发布；“已勾选”不等于租户已生效。

### 获取正确的 Open ID

在开放平台的用户 ID 查询工具或 API 调试台中，选择**此机器人所属应用**，使用用户选择功能查询自己的 `open_id`。如果工具要求通讯录授权，只授予完成查询所需的范围。不同租户的页面入口可能不同。

也可以在同一应用的消息事件调试信息中确认发送者的 `sender.sender_id.open_id`；不要把整个事件负载发给 AI。必须是 `ou_` 开头，不能用手机号、邮箱、`user_id`、`union_id` 或另一应用取得的 Open ID 替代。

**通过条件：** 机器人可私聊，所需权限已生效，消息和卡片事件已订阅，取得当前应用下的自己的 Open ID。

## 第五步：本机凭证与钥匙串

在“IM 连接”添加飞书连接，填写自己的 App ID、App Secret。首次只把自己的 Open ID 填入“用户白名单”和“管理员”；`/new` 表单需要管理员权限。选择独立群 `group`，开启自动创建会话。共享群及历史导入留待首次成功后再启用。

Verification Token、Encrypt Key 为可选字段，按所用长连接及飞书后台实际配置填写；不要凭猜测生成。App Secret 不放进 JSON、环境变量、AI 聊天或终端历史。

保存时，macOS 可能请求钥匙串访问。只允许自己安装并确认身份的 IM Agent / 后台程序访问，解锁当前登录用户钥匙串。App ID 等密文保存在 `desktop.sqlite`，随机 AES 主密钥保存在系统钥匙串服务 `io.im-agent.desktop` 中；数据库本身并非整体加密，普通配置和业务记录仍需保护。

| 提示 | 处理 |
| --- | --- |
| 系统凭证库不可访问 / 无法保存主密钥 | 检查登录钥匙串是否解锁、是否拒绝了本应用授权；允许后重试保存 |
| 系统凭证库中缺少原主密钥 | 已有密文对应的密钥缺失，恢复原钥匙串及匹配备份；不要删除数据库、随机创建新密钥或关闭加密 |
| 解密失败：密文或主密钥不匹配 | 核对数据库与钥匙串是否来自同一套备份；停止启动，不靠反复覆盖修复 |
| 更新应用后再次提示授权 | 核对新程序来源与签名后再允许；不能默认向任意请求者授权 |

客户端和后台须以同一 macOS 用户运行；不要用 `sudo` 启动。复制别人的数据库不能完成配置。密钥丢失且无备份时，需要单独设计恢复方案，不能在首次配置指导中自动清空数据。

**通过条件：** 保存成功，必填凭证标记“已加密保存”；启动桥接时没有解密错误。

## 第六步：网络与启动状态

| 链路 | 必要条件 | 如何判断 |
| --- | --- | --- |
| 构建依赖 | 能访问 GitHub、所配置的 Go 模块代理/校验服务 | 下载依赖成功；仅构建阶段需要 |
| 飞书 HTTP API | DNS、TLS 与出站 HTTPS 可用，核心 API 为 `open.feishu.cn:443` | 应用鉴权和收发成功；不要以打开官网代替鉴权检查 |
| 飞书长连接 | 允许 SDK 返回的 WebSocket 网关地址及 TLS 长连接，防火墙/代理不能持续断连 | 已连接且收到新消息事件；网关域名随服务配置变化，不只放行 API 域名 |
| 飞书附件 | 允许资源 API 及实际返回的合法资源地址 | 下载/上传结果有明确回执；纯文本成功不证明附件成功 |
| 模型服务 | 实际 Codex 进程能访问所配置服务；本地代理持续在线 | Codex 自身完成一轮模型请求 |
| 本机桌面 | 回环端口可用、不是其它进程的端口 | “检测桌面与连接入口”显示入口可用 |

终端联网不代表从 Finder 启动的 GUI 或后台继承了同样代理变量。发生代理问题时记录失败发生在构建、飞书、模型还是回环连接，不复制包含代理密码的环境变量。不设置永久关闭 TLS 校验，也不把本机端口暴露出去作为解决办法。

保存后从概览启动桥接；后台运行中、飞书已连接、桌面入口可用分别检查。已有任务时先等完成再停止桥接应用配置，不因为改配置而强停。

**通过条件：** 桥接运行，飞书已连接，桌面入口可用，等待首次任务验证。

## 第七步：首条任务，只提交一次

1. 用自己的管理员账号私聊机器人，发送 `/new`。
2. 应收到“新建 Codex 会话”表单，项目、模型、思考程度来自实际 Codex。没有模型选项时按版本兼容问题处理。
3. 选择“无项目（自动分配目录）”或一个无敏感内容的测试目录，选择已有模型及支持的思考程度。
4. 首问填写：`只回复 IM_AGENT_READY，不调用工具、不修改文件。` 点击一次“创建并开始”。表单不设等待有效期，可稍后处理；已提交或取消的表单不能重复执行。
5. 进入新建的会话群等待。**表单首问已经会自动尝试执行，不要到新群再发一次相同问题。** 自动切换关闭时，如提示等待目标桌面会话，手动打开新会话后观察原请求。
6. 核对桌面目标会话确实产生该轮回复，飞书对应群也收到回复。模型可能不逐字输出标记，应核对请求归属，不把别的轮次回复当作成功。
7. 在该已绑定群发送 `/status` 查看状态；私聊未绑定入口的 `/status` 不是完整验收。

| 阻碍 | 先检查 |
| --- | --- |
| 找不到机器人或无法私聊 | 应用是否发布、机器人能力和用户可用范围 |
| `/new` 无表单 | 连接收到消息计数、白名单 Open ID、管理员资格、消息事件、卡片发送权限 |
| 表单提示项目/模型读取失败 | 实际 CLI 的协议能力与模型认证，不是飞书建群问题 |
| 点击表单无结果 | 卡片回调订阅、操作者是否为发起人、表单是否过期 |
| 创建群失败 | 群创建/机器人管理权限、应用成员可见范围与租户限制 |
| 等待桌面 / 本条未发送 | 桌面入口、准确目标会话、草稿和编辑器状态 |
| 已提交但未确认 | 在桌面核对原轮次及客户端记录，不重新提交 |
| 桌面有回复，飞书没有 | 回复关联与投递状态、发送/更新权限、网络；未知送达不自动重发 |

**通过条件：** 单次首问执行，回复进入正确群，状态及投递证据对应同一请求。若继续使用附件、共享话题、历史导入或归档，逐项另验；不把基础收发通过当作全部功能通过。
