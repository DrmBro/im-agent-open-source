# 代码清理与冗余设计分析

核对日期：2026-10-28。本文区分已经删除的不可达代码与仍有真实调用、需要后续重构的设计。

## 本轮已完成

- 删除固定 `nativeMode := false` 后不可达的本机 WebSocket 服务、能力令牌握手、CLI 队列代理和请求过滤状态。辅助 App Server 保持 stdio 通道。
- 删除无人调用的 `desktopComposerTurn`，以及仅为它服务的深层链接启动、CLI 输出解析和旧队列启动代码。
- 删除只转调 `selectedModelTurn` 的 `desktopQueueTurn` 包装，正式桌面提交直接进入协议提交函数。
- 删除无人调用的 `getOrCreateNew`、`safeError`、`imageOnly`、`requestTelemetryText` 及其专用计数格式化函数。
- 将仍在使用的 7 个桌面日志观察和通知函数从 `native_queue.go` 移到 `desktop_rollout.go`，并将保护桌面观察引用的锁改名为 `desktopTurnsMu`。
- 删除观察缓存中只有赋值、没有读取的 `header` 字段。
- 移除设置页中不再影响正式提交的自动切换会话、保留草稿、自动恢复草稿三个开关；保留旧配置字段，兼容已有配置的读取和保存。

相对本轮开始时保存的源码快照，以上变更净减少 763 行（不计本文）。未删除数据库、回执、恢复审计、用户会话、发布备份和历史草稿。

## 建议按优先级收敛的设计

| 优先级 | 设计与证据 | 建议 | 不能直接删除的原因 |
| --- | --- | --- | --- |
| 高 | `desktop_rollout.go` 的 `readDesktopRolloutUntil`、`recovery_observation.go` 的 `ReadRecoveryObservation`、`final_reply_projection.go` 的 `finalRepliesAtCompletion` 都在解释用户归属、最终回复和完成事件。会话摘要与状态已共用观察器，但请求完成通知仍未完全统一。 | 提取纯粹的“轮次完成证据”解析器，由实时投递、请求恢复、等待通知共同消费；各调用方只保留自己的持久化进度和通知职责。 | 各自关联对象不同：会话视图允许追加输入，单条 IM 请求要求确切归属；不能把会话级完成直接算作某条请求已回复。 |
| 中 | `bridge/presentation.go` 的 `presentOne` 与 `bridge/bridge.go` 的 `refreshRecentConversation` 均执行读取摘要、检查保留策略、更新远端卡片、保存来源。两者已有互斥锁，但更新逻辑仍重复。 | 提取同一个摘要更新函数，周期扫描和完成通知只负责触发；重试、错误记录和来源更新时间统一。 | 周期路径还负责首次建卡、改名，完成路径只更新既有卡片，不能简单互相替换。 |
| 中 | `store/sync_health.go` 的 `SyncHealth` 为每个会话执行多组关联聚合；`bridge/live_mirror.go` 在每轮同步结束获取整份统计。 | 先合并消息与分片的分组查询，再按会话变更更新诊断缓存；明确缓存更新时间及数据库失败状态。 | 统计来自真实投递账本，不能用内存“发送成功”代替持久回执；当前尚未进行性能测量，不能声称它已经造成瓶颈。 |
| 中 | 旧输入框路径的 `sendPrompt`、导航和草稿保护底层实现仍被现有测试引用；正式提交已不再调用它们。 | 单独决定是否保留编辑器适配能力。若彻底退役，应同批移除相应专用测试、嵌入脚本及仅服务旧路径的选项。 | 本轮保留现有测试引用；历史草稿查看和导出仍是真实功能，不能随输入框实现一起删掉。 |
| 低 | `native_queue`、`desktop_queue` 在正式桌面提交中都进入同一协议路径，名字与当前实现不完全一致。 | 在配置边界把旧值规范化为明确的桌面协议模式，保留旧配置读取映射，界面只显示实际能力。 | 直接删除枚举值会破坏已有配置加载。 |

桌面审批的版本映射不是无用代码：它用于识别当前安装版的内部模块。可以继续集中能力检查和明确不兼容状态，但不能仅为减少代码而删除身份核验、原请求指纹或回执检查。
