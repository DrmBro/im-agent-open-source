# 远程状态与恢复边界

本次以本机账本为准补强飞书远程入口。任务事件、模型执行结果、逐片送达和展示卡回执各自保留，不用网络连接状态推断模型是否执行或消息是否送达。

## 状态展示

任务历史的状态标签和飞书请求卡来自 `internal/store/request_state.go` 的同一套有序规则。看板 SQL 由这些规则生成，历史任务与请求卡直接按规则求值。

| 已确认事实 | 展示含义 |
| --- | --- |
| 执行完成，并且回复确认送达 | 已回复 |
| 执行完成，回复清单待核对或尚未全部送达 | 模型已完成，回复待核对或同步中 |
| 存在送达未知的回复分片 | 回复送达待核对，不自动重发该未知分片 |
| 存在明确失败、仍待投递的分片 | 回复发送失败，沿用原投递重试机制 |
| 旧事件为 `done`，缺少执行和送达证据 | 结果待核对 |
| 未提交输入因权限或绑定失效而被拒绝 | 请求已关闭，未自动重放 |

逐片未知和明确失败优先于聚合送达字段。以上判定仅影响展示，不改写原始执行与投递证据。桌面发起、未关联到 IM 请求的轮次仍单独展示日志观察结果，不把模型完成描述成飞书回复送达。

## 断线与重启

普通连接重连继续使用原持久队列和投递账本；恢复连接本身不重新发送模型输入或审批选择。

重启时，处于开始处理、准备会话或下载附件阶段，且没有执行结果记录、提交意图和消息来源记录的输入，才能恢复到本地排队。已有提交证据的排队记录，以及桌面等待、草稿处理、提交、执行等待和回复同步等未完成阶段，进入原请求核对。执行完成和送达结果仍以各自账本为准，不因停止观察而否认已有结果。

数据库暂不可读不等同于撤权。普通停止也不等同于用户取消；明确未提交的排队记录可以在后续启动时继续调度。

## 权限与会话失效

恢复收件、恢复调度、工作者开始处理及最终提交钩子均复核权限或绑定。白名单、连接设置继续使用本次启动的配置快照；保存配置不会立即修改正在运行的服务，重启桥接后生效。

原发送者被移出白名单、原连接被移除、会话关闭或目标绑定改变时，明确尚未提交的旧输入以 `rejected` 状态保留，不跨会话转发。即使之后重新授权，也不会自动复活已经拒绝的旧请求。既有提交意图或执行证据不清除，不把结果未知的任务改为可以重发。

关闭会话在同一事务中取消尚未执行的模型控制入口，并撤销尚未响应的桌面审批。正在响应或响应结果未知的记录保留原样。关闭远程入口不替用户向桌面发送拒绝；原有会话关闭流程对活跃任务的处理保持原约定。

旧控制卡、审批卡和报告入口执行前仍核对原请求、卡片回执、当前活跃会话、绑定地址及操作者权限。创建表单首问使用独立的表单来源核验，不要求它具有普通 IM 收件记录。

## 本次核对范围

源码差异审查、Go 格式及语法解析、前端 JavaScript 语法检查。按本地协作约定，不新增测试文件、不编译、不运行测试，也不安装或重启现有服务。断网、异常退出和真实平台收发的运行效果尚未验收。
