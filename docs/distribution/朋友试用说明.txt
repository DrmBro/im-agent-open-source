IM Agent — macOS 开发预览版

重要：本安装包尚未使用 Developer ID 发布签名，未经过 Apple 公证。
macOS 可能阻止下载后的程序打开。请勿关闭 Gatekeeper、移除系统安全保护，或执行来历不明的绕过命令。
如果系统阻止运行，请把完整提示反馈给提供安装包的人，由其提供正式签名、公证版本。

一、支持范围
- 本包为 Apple Silicon（M 系列芯片）Mac 版本，不适用于 Intel Mac、Windows、iPhone 或 Android。
- 当前开发机器为 macOS 15.0.1；其它系统版本和全新机器尚未完成兼容验收。
- 这是公开开发预览包，不承诺稳定性；正式签名、公证及完整兼容验收仍待完成。
- IM Agent 本体不需要安装 Go 或 Node 开发环境；你自己的 Codex 安装方式可能有额外要求。

二、安装
1. 打开 DMG，将 IM Agent.app 拖到 Applications（应用程序）文件夹。
2. 从“应用程序”或启动台打开 IM Agent。不要直接在磁盘映像中长期运行。
3. 包内只有一个客户端 App；点击“启动桥接”后，它会管理独立后台。
4. 关闭客户端窗口不会停止后台；需要停止时，在概览中点击“停止桥接”。
5. 登录自启默认不开启，是否启用由你自己决定。

三、首次使用前准备
1. 安装并配置你自己的 Codex，确认它本身可以正常使用。IM Agent 不包含模型账号、授权或订阅。
2. 桌面提交模式需要兼容的 Codex 桌面应用，以及仅监听本机回环地址的连接入口。
   在客户端“Codex 配置 → 桌面启动与连接”点击“检测桌面与连接入口”。
   “重新检测本机配置”只检查配置来源，不代表桌面入口可用；需要明确看到“入口可用”。
   该入口依赖桌面版本行为，当前不能承诺所有版本都兼容。不要把调试端口开放到公网或局域网。
3. 准备你自己的飞书机器人应用、相关消息权限和长连接配置。
4. 在“IM 连接”里新增飞书连接，填写自己的应用凭证、用户白名单和管理员，保存配置。
   凭证只在本机配置，不要把密钥发给提供本包的人，也不要使用对方的配置数据库。
5. 从概览启动桥接，确认飞书显示已连接，再用一个无敏感内容的新任务验证收发。

四、数据与风险
- 本包不带发布者的运行数据库、配置、钥匙串、会话、附件或草稿。
- 你的配置、会话映射和投递记录保存于本机用户数据目录；凭证由系统钥匙串和本机加密保护。
- 模型请求会使用你本机 Codex 所配置的服务；同步到飞书的消息由相应会话成员可见。
- 首次试用不要使用重要草稿或敏感业务资料；草稿自动恢复属于实验功能，默认不启用。
- “已提交但未确认”不等于没有执行，遇到此提示不要直接重发原任务。
- 当前元数据主要来自本机会话日志；真实 TTFT 尚未采集，缺失数据不按零展示。

五、后续升级
1. 等当前任务结束，在旧客户端停止桥接，并正常退出窗口。
2. 保留本机用户数据目录和钥匙串，不要通过删除数据来升级。
3. 用新安装包替换“应用程序”中的 IM Agent.app。
4. 打开新版，先点击“更新后台程序（需先停止桥接）”，再启动桥接。
5. 客户端与后台分别升级；仅替换 App 不会热替换正在运行的后台。
